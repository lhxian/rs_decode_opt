在[git-internal](https://github.com/libra-tools/git-internal)仓库的基础上，对其中的**decoder**部件(对git仓库中的pack文件进行对象的还原，包含zlib解压和delta还原两个过程)进行性能优化。
- 原有仓库的解码建立在字节流格式上，针对中小型(pack文件100MB-500MB)、文件型仓库的pack文件进行特定场景优化。
- 在无.idx文件的场景下，受限于zlib解压方案，原有仓库使用流式解压和LRU缓存维护策略，在多线程解压对存在依赖的对象使用朴忙等待的朴素调度方案，导致**delta**对象还原存在气泡而并行效率不高。优化后通过构建object的依赖图，维护object的引用计数，精确淘汰过期缓存对象。同时生产者消费者模式，维护就绪队列，使得生产者能做到快速响应，减少消费者等待时间。
- 依赖图构建带来zlib的二次解压问题，但第二轮zlib解压可并行化，总体上看仍具有性能上的收益。
- 在中小型文件上，100MB~200MB的pack文件，16G8核Ubutu机器上解码时间从2.5s降低至约1.5s，4G2核Ubuntu机器上解码时间从5s降低到2-3s。
